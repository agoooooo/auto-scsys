# 产品设计概要

## 1. 产品定位

面向个人及小型团队的 Android 自动化工具。产品由控制端和受控端组成，作为两个分开的 Android 客户端交付：控制端 Android App（以及 Web 后台）管理受控设备并下发脚本运行任务；受控端 Android App 接收指令、执行任务并回传状态。普通用户可在客户端注册账号。

产品先聚焦“让手机可靠完成一项具体自动化操作”，再根据实际使用反馈扩展管理、计费和自动化能力。

## 2. 第一阶段目标

验证从控制端发起到受控设备执行的完整闭环：

1. 管理员创建或停用用户。
2. 控制端用户登录 Web 后台或独立的控制端 Android App，并绑定/管理自己的受控 Android 设备。
3. 管理员或用户发布自动化任务；任务所有者或已获任务访问权限的用户，可在自己的受控设备上直接派发已发布版本，无需逐设备分发或接收确认。
4. 控制端从 Web 后台或控制端 App 选择受控设备和已发布脚本，下发运行指令。
5. 受控端验证服务端指令后获取脚本并启动；Android 系统权限仍须由设备用户按系统流程授予。执行期间显示状态和停止入口。
6. 控制端可查看受控端的排队、运行和结束状态；任务结果可在控制端和受控端查看。

第一阶段建议只支持一个明确的自动化场景，例如使用 OCR 识别固定文字并执行相应操作，不以通用自动化平台为目标。

## 3. 主要功能

### Android App

- 普通用户可自助注册：姓名、邮箱和至少 6 位密码；首版不强制邮箱验证，邮箱须唯一且格式有效。自助注册只创建普通用户，不能创建管理员。
- 常用账号功能：登录、退出、记住登录状态、会话过期提示、查看/修改个人资料和登录后修改密码。
- 密码遗忘时可申请邮箱验证码并重设密码；此功能依赖邮件发送服务，邮件服务未配置前不开放重置入口。
- **控制端 App（独立应用）：**登录/注册、管理已绑定受控设备、选择已发布脚本和目标设备、下发/停止任务，并查看执行状态和结果；不包含受控设备的脚本执行运行时。
- **受控端 App（独立应用）：**登录并将本机绑定为受控设备，接收控制端指令，获取脚本并运行，显示状态、结果和本机停止入口；任务列表以卡片展示，点击“启动”直接运行已发布任务，不增加逐次脚本查看确认；不提供控制其他设备的任务派发界面。
- 受控端可在本机查看可用任务及其版本；本机手动运行不替代控制端远程下发流程。
- 常用设备功能：查看设备名称、型号、在线状态和最近活跃时间；控制端在线设备组默认展开、离线设备组默认折叠，已停用设备不展示；支持用户单独解绑自己账号下的离线设备。解绑需确认，服务端停用该设备并撤销待处理请求及设备授权。
- 常用使用体验：清楚的首次使用引导、表单校验、加载/空列表/网络错误提示、运行历史和关于/帮助入口。控制端与受控端均显示最近 10 条服务端运行历史；点选历史卡片可查看任务、状态、版本、设备、起止时间、结果及运行标识。已结束任务通过历史查阅，不再另设“最近一次运行”卡片；当前执行中的任务仍显示状态和相应操作。
- 远程任务运行时显示系统通知、当前状态和停止入口。
- 展示任务运行状态、结果和基础日志。
- 在使用屏幕捕获、无障碍等能力前说明用途并取得用户授权。
- 获取服务器发布的任务更新；更新失败时保留可用版本。

### 管理后台

- 管理员登录，创建、查看和停用用户。
- 查看用户绑定的设备及其最近活跃状态。
- 上传、发布和暂停任务版本，查看发布状态。
- 控制端用户可从 Web 或控制端 App 选择自己的受控设备，发起、跟踪和停止已发布脚本的运行；Android 控制端和受控端均可查看并点选运行历史卡片，以检查单次运行详情。
- 任务所有者或已获任务访问权限的用户，其设备可自动同步已发布脚本版本并直接派发运行；无需逐台设备分发或设备确认。运行指令仍受账号、设备归属、任务访问权限和 Android 系统权限约束。
- 查看基础任务运行记录，关联用户、设备和任务版本，便于排查问题。
- 由管理员设置账号状态及基础设备数量限制。

### 服务端

- 提供普通用户自助注册、账号认证、个人资料与密码管理、设备绑定、任务清单与任务包分发接口。
- 提供密码重置邮件验证码流程；在未配置邮件发送服务前，此功能保持关闭。
- 对用户、设备和任务进行授权校验。
- 保存任务版本、设备状态和基础运行记录。
- 对发布的任务包进行完整性校验，并仅向授权设备提供任务。

## 4. 基本角色

- **管理员：**管理用户、受控设备、脚本发布和账号可用状态；可通过 Web 或控制端 App 执行其权限范围内的设备操作。
- **控制端用户：**通过 Web 后台或控制端 App 管理自己有权操作的受控设备，下发、跟踪和停止任务。
- **受控端设备：**登录绑定到用户账号的 Android 设备，接收服务端验证过的指令并执行任务。

控制端是操作入口，受控端是任务执行端，作为分开的 Android 应用安装和运行。Web 和控制端 App 共用服务端 API 与同一套设备授权规则；两个 Android 客户端可共享协议/API 模型等非 UI 代码，但不合并成一个应用或通过模式开关切换。第一阶段不实现复杂的组织层级与细粒度权限体系。

## 5. 安全与运行原则

- 用户对屏幕捕获、无障碍等敏感能力拥有明确授权和撤销入口。
- 受控端只接受已认证控制端对其有权限操作的任务指令；Web 和控制端 App 使用相同授权规则。
- 远程运行期间遵循 Android 后台执行限制，保持运行可见并提供停止入口；屏幕捕获、无障碍等系统权限仍由设备用户明确授予。
- 任务运行状态、失败原因和关键操作应可追踪；避免在日志中记录不必要的敏感信息。
- 任务更新与 Android App 更新分开处理：后台管理 Python 任务发布；App 本身按 Android 平台的正常安装和更新流程交付。
- 账号、设备和任务权限由服务端校验，不能仅依赖客户端界面限制。

## 6. 第一阶段暂不实现

- 在线支付、自动续费、订单、退款和发票。
- 复杂的多租户组织、精细角色权限和企业级审计报表。
- 任意 Python 包的完整兼容性保证、完整 Python IDE 或通用工作流编排。
- 多种视觉识别模型和大量自动化场景。
- 静默安装或绕过 Android 权限限制。
- 实时推送、批量设备编排、定时任务及复杂工作流编排。
- 邮箱验证注册和管理员自助注册。

后续可先通过服务端可配置的账号状态和设备数量限制预留收费能力；在验证需求和收费模式后，再迭代套餐、订单与支付。

## 7. 迭代方向

第一阶段完成 Web 和独立控制端 App 两种控制入口、独立受控端 Android 执行应用、设备管理、任务下发/停止和状态追踪。之后根据试用反馈逐步扩展识别能力、设备运维、团队管理与收费功能；每次迭代优先验证明确的用户需求和端到端体验。
