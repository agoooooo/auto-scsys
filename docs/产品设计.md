# 产品设计概要

## 1. 产品定位

面向个人及小型团队的 Android 自动化工具。产品由官网、控制端和受控端组成，作为两个分开的 Android 客户端交付：公开官网介绍产品并引导用户了解和开始使用；控制端 Android App（以及 Web 后台）管理受控设备并下发脚本运行任务；受控端 Android App 接收指令、执行任务并回传状态。普通用户可在客户端注册账号。

产品先聚焦“让手机可靠完成一项具体自动化操作”。官网是面向未登录访客的公开产品与品牌入口；Web 控制台是需要登录的产品操作入口，不再提供离线 Demo 模式。控制台内管理员管理平台范围内的用户、设备、任务和审计，普通用户管理自己的设备、创建并编写脚本、发布版本和运行任务；控制台按登录角色展示对应工作区，不为普通用户和管理员另建两套 Web 产品。

## 2. 第一阶段目标

验证从控制端发起到受控设备执行的完整闭环：

1. 管理员创建或停用用户。
2. 控制端用户登录 Web 后台或独立的控制端 Android App，并绑定/管理自己的受控 Android 设备。
3. 管理员或用户发布自动化任务；任务所有者或已获任务访问权限的用户，可在自己的受控设备上直接派发已发布版本，无需逐设备分发或接收确认。
4. 控制端从 Web 后台或控制端 App 选择受控设备和已发布脚本，下发运行指令。
5. 受控端验证服务端指令后获取脚本并启动；Android 系统权限仍须由设备用户按系统流程授予。执行期间显示状态和停止入口。
6. 控制端可查看受控端的排队、运行和结束状态；任务结果可在控制端和受控端查看。

第一阶段建议只支持一个明确的自动化场景，例如使用 OCR 识别固定文字并执行相应操作，不以通用自动化平台为目标。

## 3. 主要功能

### Android App

- 普通用户可自助注册：姓名、邮箱和至少 6 位密码；首版不强制邮箱验证，邮箱须唯一且格式有效。自助注册只创建普通用户，不能创建管理员。
- 常用账号功能：登录、退出、记住登录状态、会话过期提示、查看/修改个人资料和登录后修改密码。
- 密码遗忘时可申请邮箱验证码并重设密码；此功能依赖邮件发送服务，邮件服务未配置前不开放重置入口。
- **控制端 App（独立应用）：**登录/注册、管理已绑定受控设备、选择已发布脚本和目标设备、下发/停止任务，并查看执行状态和结果；不包含受控设备的脚本执行运行时。
- **受控端 App（独立应用）：**登录并将本机绑定为受控设备，接收控制端指令，获取脚本并运行，显示状态、结果和本机停止入口；任务列表以卡片展示，点击“启动”直接运行已发布任务，不增加逐次脚本查看确认；不提供控制其他设备的任务派发界面。
- 受控端可在本机查看可用任务及其版本；本机手动运行不替代控制端远程下发流程。
- 常用设备功能：查看设备名称、型号、在线状态和最近活跃时间；控制端在线设备组默认展开、离线设备组默认折叠，已停用设备不展示；支持用户单独解绑自己账号下的离线设备。解绑需确认，服务端停用该设备并撤销待处理请求及设备授权。
- 常用使用体验：清楚的首次使用引导、表单校验、加载/空列表/网络错误提示、运行历史和关于/帮助入口。控制端与受控端均显示最近 10 条服务端运行历史；点选历史卡片可查看任务、状态、版本、设备、起止时间、结果及运行标识。已结束任务通过历史查阅，不再另设“最近一次运行”卡片；当前执行中的任务仍显示状态和相应操作。
- 远程任务运行时显示系统通知、当前状态和停止入口。
- 展示任务运行状态、结果和基础日志。
- 在使用屏幕捕获、无障碍等能力前说明用途并取得用户授权。
- 获取服务器发布的任务更新；更新失败时保留可用版本。
- 控制端与受控端 App 均可在前台检查并下载后台发布的新 APK；Android 系统安装器负责签名兼容性检查和最终安装确认，不支持静默安装。

### Web 管理后台与用户工作台

- 生产级 Web 管理后台使用 React、TypeScript、Vite 和 Ant Design；脚本编辑器使用 Monaco Editor。前端只调用现有 FastAPI，不在浏览器或服务端执行用户脚本。
- **后台系统功能清单：**
  - **工作台总览：**查看平台用户、设备、任务和运行情况的摘要，快速进入需要处理的管理模块。
  - **用户与账号：**创建、检索、查看和启用/停用普通用户，调整设备数量上限；管理员账号不开放自助注册。
  - **设备管理：**查看全平台设备及在线状态、最近活跃时间和所属用户；按状态筛选并处理设备生命周期。普通用户只能查看和解绑自己名下的设备。
  - **任务与脚本：**检索和管理任务，查看版本与发布信息，发布/切换脚本版本，管理任务访问权限，并暂停或恢复任务。脚本只在获授权的受控设备上执行。
  - **运行记录：**按状态或关键词检索运行记录、查看执行状态和安全结果摘要、导出记录；管理员可向有权限的在线设备派发任务，必要时跟踪或停止运行。
  - **权限与操作审计：**服务端按角色、资源归属和状态校验每项操作；管理员可查阅关键操作审计。界面隐藏不构成权限控制。
  - **App 自动更新：**管理员查看并发布控制端、受控端 APK，填写版本和更新说明；设备前台检查并下载新版本，随后由 Android 系统安装器向用户请求确认。发布 APK 必须递增 versionCode 并使用与设备已安装应用兼容的签名密钥。
  - **异常提醒与生产运维告警：**作为后续能力规划，按优先级汇总设备离线、运行失败、发布异常及服务/备份故障，并支持配置通知渠道和责任人；当前版本不提供完整的后台告警中心或告警投递服务。
- **管理员工作区：**管理员登录后使用上述平台级管理功能；用户、设备、任务、运行记录及审计数据均受服务端管理员权限校验。
- **普通用户工作区：**普通用户登录后只看到并操作自己账号拥有的资源；查看自己的设备及在线/最近活跃状态，解绑自己的设备；创建自己的任务和脚本，在 Monaco 编辑 Python 草稿、自动保存和恢复草稿，查看不可变版本历史/差异并发布新版本或切回旧版本。
- 用户工作区可从 Web 或控制端 App 选择本人有权操作的在线受控设备，发起、跟踪和停止已发布脚本的运行；查看本人可访问任务的运行历史和详情。Android 控制端和受控端也可查看运行历史。
- 任务所有者或已获任务访问权限的用户，其设备可自动同步已发布脚本版本并直接派发运行；无需逐台设备分发或设备确认。运行指令仍受账号、设备归属、任务访问权限和 Android 系统权限约束。
- 用户新建脚本时填写名称、说明、脚本入口和所需能力声明；编写内容自动保存为可恢复草稿。发布生成带版本号、更新说明和 SHA-256 的不可变版本；差异对比和版本回切不得改写历史版本。能力声明用于用户理解执行要求，不代表服务端静态安全审查，也不替代 Android 系统授权。
- 用户设备解绑、脚本发布/版本切换和任务运行均提供明确状态及必要的二次确认；列表提供搜索、分页、加载/空态/错误态。关键写操作由服务端按操作者、角色、资源所有权和状态校验，并记录审计。
- 管理员和普通用户工作区都必须适配手机浏览器和平板，不把移动端视为只读预览：窄屏使用可折叠导航、单列/自适应布局，表格提供卡片化或明确可横向查看的呈现，表单和确认弹窗可在小屏内滚动完成；编辑器在手机竖屏及横屏均可输入和保存，长脚本允许在编辑区内滚动。
- 移动端操作不能依赖悬停；主要按钮、菜单、选择控件和危险操作有清楚标签及适合触控的间距/命中区域。保存状态、运行状态、权限提示和错误信息在小屏上仍完整可辨，不得因固定宽度或横向溢出遮住关键操作。

### 产品官网

- 建设面向公众的独立官网，说明 FlowPilot 是什么、控制端与受控端如何协作、主要使用场景和开始使用方式；官网不承担登录后的设备、脚本或用户管理。
- 首期以中文响应式产品介绍页为主，包含品牌导航、首屏产品定位与主要行动入口、核心能力/使用流程、双端 App 介绍、常见问题和页脚；提供清晰入口前往 Web 控制台，以及在正式分发渠道确定后前往对应 App 获取页面。
- 视觉与文案应体现可信、清晰、易上手的 Android 自动化产品形象；通过界面示意或经批准的真实截图解释操作流程。不得使用未经证实的用户规模、效果数据、安全认证或客户背书。
- 手机优先适配手机竖屏、横屏、平板和桌面；导航、行动按钮、图片/示意图与文字在窄屏易读、可触控，不产生页面级横向溢出。支持键盘导航、语义化结构、足够的颜色对比度和图片替代文本。
- 官网公开内容仅使用经审核的静态产品资料，不显示账号、设备、运行记录等私有数据；隐私政策、服务条款和联系/反馈入口作为上线内容准备。下载按钮在渠道、版本和签名发布流程确认前不得提供虚假或失效链接。
- 官网和 Web 控制台属于不同访问场景。访客从官网进入控制台后仍须通过服务端认证；官网不得内嵌管理后台数据或弱化其访问控制。

### 服务端

- 提供普通用户自助注册、账号认证、个人资料与密码管理、设备绑定、用户自有任务/脚本管理、草稿保存和恢复、任务清单与任务包分发接口。
- 提供密码重置邮件验证码流程；在未配置邮件发送服务前，此功能保持关闭。
- 所有管理和用户工作区 API 按角色和资源所有权授权；用户不得读取或修改其他用户的设备、草稿、任务、脚本及运行记录，也不得调用管理员级用户管理和全局审计操作。
- 保存任务版本、设备状态和基础运行记录。
- 对发布的任务包进行完整性校验，并仅向授权设备提供任务。

## 4. 基本角色

- **管理员：**管理用户、受控设备、脚本发布和账号可用状态；可通过 Web 或控制端 App 执行其权限范围内的设备操作。
- **普通用户/控制端用户：**通过 Web 用户工作区或控制端 App 管理自己的受控设备及脚本，下发、跟踪和停止任务；不能访问其他用户资源或管理员操作。
- **受控端设备：**登录绑定到用户账号的 Android 设备，接收服务端验证过的指令并执行任务。

控制端是操作入口，受控端是任务执行端，作为分开的 Android 应用安装和运行。Web 和控制端 App 共用服务端 API 与同一套设备授权规则；两个 Android 客户端可共享协议/API 模型等非 UI 代码，但不合并成一个应用或通过模式开关切换。第一阶段不实现复杂的组织层级与细粒度权限体系。

## 5. 安全与运行原则

- 后台编写和上传的 Python 脚本视为不可信内容：服务端只做大小、扩展名和完整性检查，不提供任意代码执行沙箱；发布前由管理员按组织流程审查脚本与能力声明，设备端按 Android 可见授权流程执行。
- Web 控制台是统一的浏览器入口，登录后依据角色提供管理员工作区或普通用户工作区；生产构建不包含离线演示数据、预填账号/密码或模拟远程运行成功状态。界面隐藏不是授权机制，服务端仍须对每个接口检查角色、所有权及关联资源。
- 用户对屏幕捕获、无障碍等敏感能力拥有明确授权和撤销入口。
- 受控端只接受已认证控制端对其有权限操作的任务指令；Web 和控制端 App 使用相同授权规则。
- 远程运行期间遵循 Android 后台执行限制，保持运行可见并提供停止入口；屏幕捕获、无障碍等系统权限仍由设备用户明确授予。
- 任务运行状态、失败原因和关键操作应可追踪；避免在日志中记录不必要的敏感信息。
- 任务更新与 Android App 更新分开处理：后台管理 Python 任务发布；App 本身按 Android 平台的正常安装和更新流程交付。
- App 更新后台仅管理当前发布版本；服务端记录包名、版本、大小和 SHA-256，不解析 APK 签名。签名由 Android 安装流程校验，发布时仍须使用兼容的持续签名密钥。
- 账号、设备和任务权限由服务端校验，不能仅依赖客户端界面限制。

## 6. 第一阶段暂不实现

- 在线支付、自动续费、订单、退款和发票。
- 复杂的多租户组织、精细角色权限和企业级审计报表。
- 独立原生移动 Web 应用/PWA；本期提供适配手机浏览器的响应式 Web 控制台。
- 任意 Python 包的完整兼容性保证、完整 Python IDE 或通用工作流编排。
- 多种视觉识别模型和大量自动化场景。
- 静默安装或绕过 Android 权限限制。
- 实时推送、批量设备编排、定时任务及复杂工作流编排。
- 邮箱验证注册和管理员自助注册。
- 多用户脚本共享/市场、团队协作审批、定时运行及跨账号设备共享。
- 官网内容管理系统、访客账号、在线营销活动管理和复杂的线索/客户关系管理；首期官网使用经审核的静态内容。

后续可先通过服务端可配置的账号状态和设备数量限制预留收费能力；在验证需求和收费模式后，再迭代套餐、订单与支付。

## 7. 迭代方向

第一阶段已完成 Web 和独立控制端 App 两种控制入口、独立受控端 Android 执行应用、设备管理、任务下发/停止和状态追踪。后台现有功能包括总览、用户和设备管理、任务/脚本版本治理、运行记录与导出、权限控制和操作审计；控制端与受控端 APK 发布及客户端自动检查/下载流程已实现，真实签名 APK 的发布升级验收仍待完成。普通用户工作台已在现有 React/TypeScript 控制台内按角色实现，包含个人设备管理、个人脚本和任务、持久化草稿及发布/回滚/运行界面，管理员工作区继续保留并与普通用户资源隔离；响应式布局与服务端/API 自动化覆盖已实现。普通用户端桌面及手机真实浏览器 E2E/真机验收尚未完成。新增官网需求，尚未设计实现或验收；异常提醒中心、正式生产告警投递和完整运维可观测性列为后续能力。生产发布还必须完成 HTTPS、S3 提供方兼容性、运维备份恢复、限流、MFA/安全评审和监控等上线门槛。
