# 产品设计概要

## 1. 产品定位

面向个人及小型团队的 Android 自动化工具。用户通过后台管理账号和手机，在手机端获取经过授权的 Python 自动化任务，并查看任务运行结果。

产品先聚焦“让手机可靠完成一项具体自动化操作”，再根据实际使用反馈扩展管理、计费和自动化能力。

## 2. 第一阶段目标

验证从任务发布到手机执行的完整闭环：

1. 管理员创建或停用用户。
2. 用户登录 Android App，并将一台或多台手机绑定到自己的账号。
3. 管理员或用户发布自动化任务；管理员分发给其他用户/设备时，接收端用户确认后设备才可获取对应版本。
4. 用户在手机上明确授权所需能力后运行任务；也可以从 Web 后台向自己的设备发起远程运行请求。
5. 远程请求经服务端验证账号、设备、脚本版本和授权后，由 Android 自动批准并启动；Android 系统权限仍须由设备用户按系统流程授予。执行期间显示状态和停止入口。
6. 任务识别目标内容并执行操作，运行状态和结果可在手机端及后台查看。

第一阶段建议只支持一个明确的自动化场景，例如使用 OCR 识别固定文字并执行相应操作，不以通用自动化平台为目标。

## 3. 主要功能

### Android App

- 用户登录和退出。
- 设备绑定与基本设备信息展示，支持同一账号管理多台手机。
- 查看可用任务及其版本，手动启动和停止任务。
- 接收 Web 后台发起的远程运行请求；服务端校验通过后由 Android 自动批准并运行，设备用户可随时停止。
- 远程任务运行时显示系统通知、当前状态和停止入口。
- 展示任务运行状态、结果和基础日志。
- 在使用屏幕捕获、无障碍等能力前说明用途并取得用户授权。
- 获取服务器发布的任务更新；更新失败时保留可用版本。

### 管理后台

- 管理员登录，创建、查看和停用用户。
- 查看用户绑定的设备及其最近活跃状态。
- 上传、发布和暂停任务版本，查看发布状态。
- 用户可为自己的设备发起远程运行；管理员可将已发布的脚本版本分发到指定设备，接收端确认后获取。远程运行经服务端授权校验后由 Android 自动批准并运行。
- 查看基础任务运行记录，关联用户、设备和任务版本，便于排查问题。
- 由管理员设置账号状态及基础设备数量限制。

### 服务端

- 提供账号认证、设备绑定、任务清单与任务包分发接口。
- 对用户、设备和任务进行授权校验。
- 保存任务版本、设备状态和基础运行记录。
- 对发布的任务包进行完整性校验，并仅向授权设备提供任务。

## 4. 基本角色

- **系统管理员：**管理用户、设备、任务发布和账号可用状态。
- **普通用户：**管理自己账号下的设备，查看并运行获准的任务。

第一阶段以单一管理后台和简单角色为主，不实现复杂的组织层级与细粒度权限体系。

## 5. 安全与运行原则

- 只运行服务端认可并通过完整性校验的任务包。
- 用户对屏幕捕获、无障碍等敏感能力拥有明确授权和撤销入口。
- 远程运行请求经服务端授权校验后由 Android 自动批准，但遵循 Android 后台执行限制，始终保持运行可见并提供停止入口；屏幕捕获、无障碍等系统权限仍由设备用户明确授予。
- 任务运行状态、失败原因和关键操作应可追踪；避免在日志中记录不必要的敏感信息。
- 任务更新与 Android App 更新分开处理：后台管理 Python 任务发布；App 本身按 Android 平台的正常安装和更新流程交付。
- 账号、设备和任务权限由服务端校验，不能仅依赖客户端界面限制。

## 6. 第一阶段暂不实现

- 在线支付、自动续费、订单、退款和发票。
- 复杂的多租户组织、精细角色权限和企业级审计报表。
- 任意 Python 包的完整兼容性保证、完整 Python IDE 或通用工作流编排。
- 多种视觉识别模型和大量自动化场景。
- 静默安装或绕过 Android 权限限制。

后续可先通过服务端可配置的账号状态和设备数量限制预留收费能力；在验证需求和收费模式后，再迭代套餐、订单与支付。

## 7. 迭代方向

第一阶段完成单一自动化场景、基础用户与多设备管理、任务发布更新和运行记录。之后根据试用反馈逐步扩展识别能力、设备运维、团队管理与收费功能；每次迭代优先验证明确的用户需求和端到端体验。
