# 技术方案概要

## 1. 方案目标

实现由公开产品官网、生产 Web 控制台、控制端 Android App 和受控端 Android App 组成的 Android Python 自动化产品。官网面向访客介绍产品并引导开始使用，不提供账号内操作；Web 控制台是需要登录、按角色提供工作区的应用：普通用户操作自己的设备和脚本，管理员管理平台资源；不另建两套控制台。控制端 Android App 与受控端 Android App 是两个独立应用，分别安装、启动和发布；官网与生产控制台使用分离的前端访问边界。Web 控制台和控制端 App 共用服务端 API，两个 Android 客户端可共享 API 客户端、数据模型等非界面代码，但不得合并成同一应用或依赖角色模式切换。目标流程包括：

1. 控制端用户登录 Web 或控制端 App，绑定并管理一台或多台受控 Android 设备。
2. 普通用户可在 Android 客户端自助注册，密码至少 6 位；首版不强制邮箱验证，注册只创建普通用户，管理员仍由现有管理员创建。
3. 客户端提供常用账号流程：登录、退出、保持登录、会话过期提示、查看/修改个人资料和登录后修改密码。
4. 普通用户在 Web 用户工作区创建自己的脚本/任务，保存可恢复草稿并发布不可变 Python 脚本版本；管理员可管理平台范围的用户、任务和版本。
5. 控制端选择目标受控设备和已发布脚本，从 Web 或 Android 客户端发起、跟踪或停止任务。
6. 受控端通过服务端校验后获取脚本并运行；执行状态和结果回传给控制端及受控端。
7. 管理员可以管理用户、设备、脚本发布和运行状态。

Android 系统权限仍按系统授权流程处理；控制端指令不能替代设备用户授予屏幕捕获、无障碍等系统能力。

## 2. 技术栈建议

| 模块 | 建议技术 | 用途 |
|---|---|---|
| 控制端 Android App（独立应用） | Kotlin、Jetpack Compose | 账号登录、受控设备管理、脚本任务下发/停止及状态查看；不含脚本执行运行时 |
| 受控端 Android App（独立应用） | Kotlin、Jetpack Compose、Chaquopy | 本机设备绑定、指令接收、脚本运行、系统权限和状态反馈；不提供任务派发界面 |
| Python 运行时 | Chaquopy | 将受支持版本的 Python 运行时集成到 Android App |
| Android 自动化能力 | Kotlin 原生 API + App 内部 Python 桥接接口 | 提供屏幕捕获结果、OCR、明确授权的交互能力给 Python 脚本 |
| Web 控制台 | React、TypeScript、Vite、Ant Design | 同一应用按服务端角色显示普通用户工作区或管理员工作区 |
| 产品官网 | 静态 Web 前端（具体框架按实施阶段确定） | 面向公众介绍产品、使用流程、双端 App 和常见问题；链接至控制台及正式 App 分发渠道 |
| 脚本编辑器 | Monaco Editor | 浏览器内编写/恢复 Python 草稿、查看版本差异及发布不可变脚本版本 |
| 服务端 API | Python、FastAPI | 认证、授权、脚本版本管理、设备状态和运行记录 |
| 主数据库 | PostgreSQL | 用户、设备、脚本元数据、权限关系和运行记录 |
| 脚本文件存储 | S3 兼容对象存储 | 保存版本化脚本包；数据库只保存元数据及存储键 |
| 部署 | Docker | 部署 API 和后台；MVP 可使用托管 PostgreSQL 与对象存储 |

现有 `demo/` 原生 JavaScript 页面仅作为旧原型和迁移参考，不进入生产 Web 镜像。生产控制台从独立 `console/` 工程构建静态资源，Nginx 提供前端并将 `/api/*` 同源代理到 FastAPI；本地开发由 Vite 提供热更新并代理 API。控制台不得包含离线假数据或模拟成功路径。Monaco 脚本编辑器只创建/发布脚本版本；服务端只验证扩展名、大小和 SHA-256，绝不在 Web/API 进程执行用户脚本。

暂不引入消息队列、Kubernetes 和微服务。Android 客户端可通过定时轮询获取更新；确有实时通知需求后再评估推送服务。

客户端常规体验包括首次使用引导、注册/登录表单验证、个人资料、会话管理、设备在线状态、任务历史、网络错误/空状态提示及帮助/关于页面。Web 控制台前端按登录用户角色控制导航和页面，但服务端必须独立校验每个请求的角色和资源所有权。普通用户仅能访问自己所有或明确授权的设备、任务、草稿、脚本和运行记录；平台用户管理、全局设备查看及操作审计只对管理员开放。邮件验证码找回密码列为账号功能，但依赖邮件服务；在邮件发送服务配置前保持关闭。注册邮箱首版不要求验证，不等于管理员账号可自助创建。

### 产品官网设计与边界

- 官网首期为中文、响应式、静态内容站点，采用独立于 `console/` 管理控制台的页面入口和构建/发布边界。可复用品牌资产和通用设计规范，不复用登录态或管理页面。
- 首页信息结构包括：品牌导航；首屏价值主张及“了解产品 / 前往控制台”行动入口；核心能力与典型使用流程；控制端和受控端职责说明；常见问题；页脚中的隐私政策、服务条款和联系/反馈入口。App 下载链接仅在正式分发渠道、版本和签名流程确定后启用。
- 页面优先适配手机，再覆盖平板和桌面；保证导航与行动入口可触控，文字层级清楚，内容和图片不造成页面级横向溢出。实现时满足基础无障碍要求，包括语义化 HTML、键盘可达、可见焦点、对比度和非装饰图片的替代文本。
- 官网只提供公开、经审核的产品信息和静态示意，不查询或展示用户、设备、脚本、运行等私有数据，不在官网执行脚本。访客前往控制台后由控制台和服务端独立执行认证及授权。
- 不宣称未经验证的性能、安全认证、客户案例或产品效果；隐私政策、服务条款及联系信息须在公开上线前由产品/运营确认。

### Web 用户工作区

- 管理员与普通用户共用 `console/`、同源 `/api` 和会话处理，根据服务端确认的角色渲染各自工作区。前端路由或菜单限制只改善体验，不构成安全边界。
- 普通用户可查看和解绑自己的受控设备，创建/编辑自己的任务及脚本，使用 Monaco 编辑器编写 Python，维护脚本能力声明和版本说明，查看已发布版本/差异、发布新不可变版本、切换当前版本、向自己有权限操作的在线设备发起/停止运行并查阅历史。
- 未发布编辑内容使用服务端草稿资源进行自动保存与恢复；草稿与正式发布版本隔离，不可作为设备端可同步或执行的版本。发布成功后创建不可变版本并记录内容哈希、发布用户及时间。
- 用户设备解绑和任务运行需明确确认；发布及版本切换显示目标任务、版本、差异摘要和能力声明。设备系统权限仍由 Android 按系统流程逐次/按会话取得。
- 普通用户与管理员工作区均采用响应式 Web 布局，覆盖手机竖屏/横屏、平板和桌面浏览器。移动断点下侧边导航转为抽屉/菜单，内容区与表单改为单列或自适应；管理数据表应提供适合窄屏的卡片视图，或保证横向滚动时列标题、关键字段及行操作仍可发现和操作。
- Monaco 编辑器及源码差异视图在窄屏保持可用：编辑区占据可用宽度和高度，工具栏/版本操作可触达，弹窗可滚动；不得把整个页面锁定为桌面最小宽度。代码本身可横向滚动，页面导航和主要操作不随代码溢出。
- 触控控件不依赖 hover/精确指针，按钮和菜单采用易触达的尺寸及间距；对话框、确认操作和通知适配软键盘与小屏可视区域。移动端应明确呈现草稿保存状态、运行状态及错误反馈。
- 以手机真实浏览器和桌面浏览器进行响应式验收；覆盖主要任务创建/编辑/恢复草稿/发布/版本切换、设备管理与运行操作，检查无页面级意外横向溢出、遮挡或不可达控件。原生 Android App 仍承担设备端执行能力，响应式 Web 不替代受控端 App。
- 第一版不建设多用户协同编辑、共享脚本市场、复杂审批、定时任务或服务端脚本执行/沙箱。

### 部署阶段安排

先在隔离的开发/预生产环境验证 PostgreSQL、S3 兼容对象存储、Web/API 与 Android 任务闭环，并完成备份和恢复演练；公网域名与 HTTPS 入口按当前项目决策留到最后上线阶段。前置验证环境不得开放到公网，不得使用真实生产凭据。现有 Docker Compose production profile 强制配置域名、Caddy HTTPS 和精确 HTTPS CORS origin，不能直接用于无域名 HTTP 预生产；需要另行提供受限的私有预生产配置或使用隔离集成测试。对外开放服务、使用真实用户凭据或分发 Release APK 前，必须完成 HTTPS、CORS、对象存储访问地址及 Android Release API 配置。

## 3. 总体结构

```text
控制端 Web 后台 ──────────────┐
独立控制端 Android App ───────┴─ HTTPS ──► 服务端 API
                                      ├─ 认证与授权
                                      ├─ 用户、设备和脚本版本管理
                                      ├─ 运行指令与状态记录
                                      ├─ PostgreSQL
                                      └─ 对象存储
                                           ▲
                                           │ HTTPS / 定时轮询
独立受控端 Android App ──────────────────┘
  ├─ Kotlin / Jetpack Compose：账号、设备、权限提示和运行状态
  ├─ Python Runtime：加载并运行已下载的用户脚本
  └─ Native Bridge：提供经用户授权的 OCR、屏幕和交互能力
```

脚本只在受控端 Android App 所在设备本地运行。Web 后台和独立控制端 App 作为同等控制入口；受控端 App 专责接收并执行任务。服务端负责身份、设备授权、脚本分发、运行指令和状态记录，不在服务端代替手机执行自动化操作。

## 4. Android 执行设计

### 4.1 Python 与原生能力的分工

- Kotlin 负责 Android 生命周期、登录态、权限流程、前台任务状态和设备 API。
- Python 负责脚本逻辑、流程编排和对 App 提供能力的调用。
- App 通过原生桥接接口向脚本提供 OCR、屏幕内容和交互等自动化能力。
- MVP 优先实现一个场景和少量接口，例如读取用户授权的屏幕内容、OCR 识别、返回结构化结果。后续再按需求增加交互能力。

### 4.2 脚本包与运行状态

- 每个脚本版本作为不可变版本保存，包含入口文件、依赖清单、脚本元数据和版本说明。
- 服务端提供版本化脚本文件和哈希，受控端下载后校验文件完整性。
- 客户端保留最近可用版本；新版本下载或校验失败时不替换已安装版本。
- 运行状态至少包括：等待设备、已接收、准备中、运行中、成功、失败、已停止和已过期。
- 前台执行时展示可见状态和停止入口。需要持续运行时使用 Android 前台服务并遵循系统通知要求，不承诺被系统强行终止后仍可无感运行。
- 远程请求需绑定脚本版本、目标设备、发起人、有效期和唯一请求 ID，并经过服务端授权校验及审计记录。

### 4.3 本地启动与系统权限

- 受控端用户可从设备本机启动已获取的脚本；控制端远程请求由受控端在服务端校验通过后自动运行，不增加逐次脚本审阅或确认流程。
- 受控端可用任务按独立卡片展示，点击“启动”直接启动所选已发布版本；脚本下载与 SHA-256 校验在执行流程中完成，系统权限仍由 Android 正常授权。
- 系统权限由 Android 正常授权流程取得；App 不尝试绕过权限、无障碍或屏幕捕获限制。
- 屏幕捕获、无障碍等敏感系统能力仍须设备用户按 Android 系统流程授予。
- 用户可以停止运行、撤销系统授权或停用设备。

### 4.4 后台远程运行

- 控制端用户可从 Web 后台或控制端 App 选择自己有权操作的在线设备和已发布脚本，发起一次远程运行请求；服务端只下发请求，不在服务端执行手机自动化。
- 所有远程请求在服务端账号、设备授权、脚本版本、请求有效期及设备空闲检查通过后，由受控端 Android 自动接收并运行；无需逐次任务审阅、确认或设置预授权。任务通过可见前台服务运行；控制端停止请求经受控端轮询传递，在脚本下一个停止检查点响应，不强制终止任意阻塞代码。
- 每条运行指令使用唯一请求 ID；受控端重复收到同一请求时不得重复启动。同一受控设备同时只运行一个任务；控制端可取消待执行请求或停止运行中的任务。
- 运行状态至少区分等待设备、已接收、运行中、成功、失败、已停止和已过期。控制端 Web 和 App 均显示请求及执行状态；两个 Android App 还展示最近 10 条运行历史，卡片可打开详情查看任务、状态、版本、设备、开始/结束时间、结果摘要及运行/远程请求 ID。已结束任务统一从历史记录查看，不单独保留“最近一次运行”卡片；当前执行中的任务仍显示必要状态和停止操作。
- 设备通过定时轮询获取请求；离线或过期请求不执行，并在后台显示明确状态。后续如需实时性，再评估推送通知；推送不绕过 Android 的后台启动限制。
- 请求要求的无障碍服务必须已由用户在 Android 设置中启用。远程 OCR/屏幕捕获在有效的持续 OCR 前台服务会话中复用该会话，否则须打开 App 并完成 Android MediaProjection 系统授权；系统授权不是任务确认，拒绝系统授权则不执行。会话结束或系统回收后必须重新授权，客户端不尝试静默恢复。后台无法发起系统授权时通知用户打开 App，授权完成后继续处理。
- 任务运行时使用 Android 允许的前台执行方式，显示持续通知、运行状态和停止入口；不支持无运行提示或不可停止的静默执行。
- 若 Android 系统不允许后台启动，应等待用户打开 App 或确认，不能尝试绕过系统限制。

### 4.5 Android App 自动更新

- 管理后台按应用类型（控制端、受控端）维护各自当前发布版本；管理员上传 APK 并填写 `versionCode`、`versionName` 和更新说明。新版本的 `versionCode` 必须高于该应用当前发布版本。
- 服务端公开版本检查和 APK 下载接口，响应包含包名、版本信息、文件大小和 SHA-256。客户端前台检查更新，下载到应用专属缓存目录后验证 SHA-256、包名和版本，再通过受限的 `FileProvider` URI 交给 Android 安装器。
- Android 安装器负责校验已安装包的签名兼容性，并要求用户确认安装；客户端不得静默安装、绕过未知来源安装设置或伪造升级成功。用户拒绝安装时保留当前应用，稍后可再次检查。
- 服务端限制 APK 上传大小并记录发布审计。服务端只核对 APK 文件及版本元数据和下载哈希，不解析或证明 APK 的签名；管理员必须使用对应应用兼容的正式签名密钥。每个应用当前只保留一个发布版本，暂不提供发布历史和后台回滚。
- Python 脚本版本更新与 Android App 更新是独立流程：前者供受控端同步和执行，后者通过 Android 系统安装器升级客户端。

## 5. 主要业务流程

### 用户上传并运行

1. 用户登录后台或 App，创建脚本并上传版本包。
2. 服务端验证文件大小、格式、入口和版本元数据，保存版本并计算内容哈希。
3. 用户在手机端选择该脚本，客户端下载并校验版本包。
4. 客户端展示来源、版本、能力说明和系统授权状态。
5. 控制端用户在 Web 或控制端 App 选择受控设备和脚本，发起远程运行请求。
6. 受控端在服务端鉴权通过后接收并运行请求；无障碍服务必须已由用户启用，远程 OCR/屏幕捕获须由设备用户完成 Android 系统授权。
7. 受控端在系统允许且用户可见的执行方式下启动 Python 脚本，通过原生桥接执行所需能力。
8. 受控端展示运行结果和错误摘要并提交必要的运行记录，控制端 Web/App 同步展示状态。

### Web 普通用户工作区

1. 普通用户登录后，服务端确认角色，控制台打开个人工作区；管理员专属导航不显示，所有服务端授权仍以请求身份为准。
2. 用户查看本人设备和任务，创建个人任务及脚本；API 在每次读取、创建、更新和删除操作中验证资源所有权。
3. 编辑器对草稿做有反馈的自动保存；离开页面或刷新后可恢复草稿。网络失败时明确提示未保存状态，不把失败请求显示为保存成功。
4. 发布时显示任务、版本、更新说明、能力声明和脚本差异；服务端验证内容大小/类型/哈希并创建不可变版本。发布不触发运行。
5. 用户选择本人有权操作的在线设备，发起远程运行；查看排队/运行/终态和历史，必要时停止运行。服务端复核设备归属、任务权限、设备状态和请求有效性。
6. 用户切回旧版本时，服务端仅调整任务的当前版本指针并写审计，不修改或删除既有版本。

### 管理员发布

1. 管理员创建或停用用户，查看其绑定设备。
2. 管理员选择脚本版本及目标用户或设备进行发布。
3. 服务端记录目标设备、脚本版本、发布者和接收状态；设备同步时只看到待确认发布的元数据及已确认版本。
4. 任务所有者或已获任务访问权限的用户，其设备自动同步任务当前发布版本并校验脚本；不要求逐台设备分发、版本授权或接收确认。设备系统权限仍由用户按 Android 系统流程授予。
5. 管理后台查看版本分配和运行结果。

脚本发布本身不会自动触发执行。远程运行是独立操作：用户从 Web 发起请求后，设备端在服务端校验通过后自动运行并记录结果；请求均设置有效期。远程 OCR/屏幕捕获任务仍须由设备用户同意 Android 系统屏幕捕获授权；在用户主动开启的可见持续会话有效期内，可复用这次系统授权，不能静默获取或跨会话恢复权限。

## 6. 服务端与数据模型

MVP 核心实体建议包括：

- **User：**账号、邮箱、状态、设备数量上限。
- **Device：**所属用户、设备标识、型号、App 版本、最近活跃时间、状态。
- **Script：**脚本名称、所有者、描述及可见范围。
- **ScriptDraft：**任务/脚本 ID、所有者、草稿内容或草稿对象存储键、更新时间及并发版本标识；与已发布 ScriptVersion 分开授权及存储。保存接口支持并发冲突识别，客户端需处理冲突，不能静默覆盖较新的草稿。
- **ScriptVersion：**版本号、对象存储键、内容哈希、入口、依赖清单、能力说明、创建者和发布时间。
- **ScriptGrant：**脚本版本对用户或设备的授权关系及状态。
- **TaskPublication：**旧管理端兼容记录；不再控制脚本同步、下载或运行权限。实际访问由任务所有者/任务访问权限决定。
- **RunAuthorization：**旧客户端兼容数据；当前 Android 客户端不使用逐任务运行预授权。
- **RemoteRunRequest：**远程运行请求及其发起人、目标设备、状态、有效期和关联运行记录。
- **RunRecord：**用户、设备、脚本版本、开始/结束时间、状态和可展示的结果摘要。
- **AuditEvent：**用户停用、设备变更、脚本发布和授权变更等关键管理操作。

所有用户拥有型资源都应有可验证的 owner 关系；读取、写入、版本发布/激活、运行记录查询均从已认证的操作者开始查询并在服务端校验 owner、关联设备/任务和角色。禁止先按客户端传入的资源 ID 无条件查出对象再只检查 UI 权限。管理员操作需另做角色校验。服务端每次签发脚本清单或下载地址时都校验用户、设备和脚本授权，不依赖客户端隐藏界面来实现权限控制。运行日志采用必要信息最小化原则，不上传脚本运行中读取到的原始屏幕内容或敏感数据，除非产品后续明确设计并取得用户同意。

## 7. API 范围

MVP 可先提供以下 REST API：

- `POST /auth/register`：创建普通用户账号；验证姓名、邮箱格式、至少 6 位密码和邮箱唯一性，不开放管理员注册，不强制邮箱验证。
- `POST /auth/login`、`POST /auth/refresh`、`POST /auth/logout`：登录、续期和退出。
- `GET /auth/recovery-status`：公开返回邮件密码找回是否已配置；Web 和 Android 登录页仅在启用时显示找回入口。
- `GET /me`：获取当前用户和账号状态。
- `PATCH /me`：更新当前用户姓名/邮箱；更改邮箱须提供当前密码。
- `POST /auth/change-password`：校验当前密码后更新密码，并撤销其他登录会话；当前会话保持有效。
- `POST /auth/forgot-password`、`POST /auth/reset-password`：请求邮件验证码及重置密码；SMTP 未完整配置时返回不可用错误。验证码仅保存服务端摘要、10 分钟失效、最多尝试 5 次，重置成功撤销所有会话；客户端在邮件服务验证前不开放入口。
- `POST /devices`、`GET /devices`、`DELETE /devices/{id}`：设备绑定、查询和解绑。
- `POST /scripts`、`GET /scripts`：创建脚本元数据和查询可访问脚本。
- `POST /scripts/{id}/versions`、`GET /scripts/{id}/versions`：上传及查询版本。
- `POST /tasks`、`PATCH /tasks/{id}`：普通用户创建和编辑自己拥有的任务；管理员可在其权限范围管理任务。任何更新均校验资源所有者/管理员角色。
- `GET /tasks/{id}/versions/{version}/source`：在确认调用者有任务访问权后读取指定脚本版本；不得向无权用户泄露源码。
- `GET /tasks/{id}/draft`、`PUT /tasks/{id}/draft`、`DELETE /tasks/{id}/draft`：用户读取、自动保存及删除其拥有任务的未发布草稿。保存接口使用递增修订号乐观并发控制；发布后以修订号删除草稿，遇到并发更新会保留新草稿。普通用户跨账号、跨所有者访问由服务端拒绝，并有草稿持久化、冲突、删除后旧修订拒绝和越权测试。
- 用户资源列表和运行历史：按登录用户限制到本人所有或明确授权的资源；不得让查询参数扩大到全平台数据。用户管理、全局审计和跨用户管理 API 限管理员。
- `POST /devices/{id}/sync`：获取当前设备可用的任务清单。
- `GET/POST /tasks/{id}/publications`、`DELETE /tasks/{id}/publications/{publication_id}`：兼容旧管理端的设备分发记录接口，不作为权限门槛。
- `POST /devices/{id}/publications/{publication_id}/accept`：兼容旧客户端接口；新客户端无须调用。
- `POST /remote-runs`：控制端为有权操作的目标设备创建远程运行请求；Web 和控制端 App 共用此接口。
- `GET /devices/{id}/remote-runs`：设备轮询待处理请求。
- `GET /remote-runs/{id}`：Web 查询单个请求的执行状态和安全结果摘要。
- `POST /remote-runs/{id}/stop`：设备所属普通用户幂等请求停止运行中的远程任务；受控端运行时轮询停止标记并在脚本停止检查点结束执行。
- `PATCH /remote-runs/{id}`：设备端客户端在服务端校验后自动批准或拒绝等待中的请求。
- `POST /runs/{id}`：受控端上报本地/远程运行终态。
- `GET /runs`：按开始时间倒序查询运行记录，返回运行 ID、任务/版本、设备、状态、开始/结束时间、结果摘要及可空的远程请求关联 ID；Android 两端各展示最近 10 条并支持逐条查看详情。
- 遗留有限预授权 API 为旧客户端兼容保留，不参与当前 Android 客户端的远程执行判断。
- `POST /runs`、`PATCH /runs/{id}`：上报运行开始、结束状态和结果摘要。
- 管理接口：用户停用、设备管理、版本发布与运行记录查询。

控制端设备列表将在线组默认展开、离线组默认折叠，且不展示已停用设备；支持按单台离线设备发起解绑。解绑前须明确提示设备停用以及待处理远程请求、设备授权和分发记录将被撤销。当前服务端 `DELETE /devices/{id}` 通过停用设备实现解绑，不会保证中止设备上已经开始的本地任务。

`POST /remote-runs` 支持 `Idempotency-Key` 请求头；相同普通用户、设备和键的同任务重试复用原请求，键被用于其他任务时返回 `409`。派发、远程批准、本地启动及运行完成会在目标设备锁内完成；数据库唯一部分索引作为最后一道约束，保证同一设备最多存在一个 `running` 运行记录。PostgreSQL 使用设备行锁，SQLite 使用写事务锁。Web 与 Android 控制端均发送幂等键，并在不确定是否送达时沿用同一键。

脚本包使用短时有效的对象存储上传/下载地址，避免通过 API 服务进程中转大文件。所有管理接口均需做角色和资源归属校验。

## 8. MVP 范围与验收

### 首版实现

- 一个管理员角色和一个普通用户角色；控制端/受控端是分开的客户端应用职责，不增加独立的复杂组织角色。
- 普通用户从客户端注册后即可登录控制端；受控 Android 设备通过同一用户账号绑定。管理员账号只由管理员创建/初始化。
- 常用账号基础体验：登录、退出、保持登录、个人资料、修改密码、会话过期处理和注册校验。控制端 Android 将会话加密保存在设备；Web 默认仅在当前标签页保持登录，用户勾选“在此设备保持登录”后保存至浏览器本地存储。Web/Android 在访问令牌过期后自动续期，服务端会话失效时提示重新登录。邮箱密码找回暂不开放，待邮件服务配置后再实现。
- 用户登录、设备绑定及多设备查看。
- Web 控制台按角色提供管理员工作区和普通用户工作区；普通用户只能操作自己的设备、任务、脚本和运行记录，管理员用户管理、全局设备管理及全局审计不向普通用户开放。
- 普通用户可在 Web 创建个人任务/脚本、使用 Monaco 编辑、自动保存和恢复服务端草稿，查看版本及差异、发布不可变版本、切回已有版本，并在发布确认中查看能力声明和变更。
- 用户可管理自己的设备，从 Web 运行自己有权访问的已发布脚本到本人在线设备，查看状态/历史并停止运行；Android 系统授权流程不变。
- 一种目标自动化场景及一组最小原生桥接能力。
- 控制端用户可从 Web 或独立控制端 App 向独立受控端 Android App 下发任务；受控端运行可见且可停止，两个控制入口均可查看状态和结果。
- 远程请求具备唯一 ID 和幂等处理；同一受控设备不会并发执行多个任务。
- 远程 OCR/屏幕捕获仍需设备用户授予 Android 系统授权；服务端脚本授权和 Android 系统权限均不能被客户端绕过。
- 运行期间显示状态、结果、日志摘要和停止入口。
- 已获任务访问权限的用户设备自动同步发布版本；控制端可直接派发运行，无逐设备发布或接收确认步骤。
- 服务端权限校验、版本哈希校验、失败保留旧版本和基础审计记录。
- 草稿保存错误、会话过期、重复发布/重试及并发草稿更新有明确状态和自动化回归覆盖；保存失败不得显示成功或丢弃尚未保存的编辑内容。

### 首版暂不实现

- 任意 Python 包的完整兼容性保证、在线 IDE 和复杂依赖构建。
- 无限制的设备集群编排、无通知静默运行、不可停止的远程执行和复杂组织角色。
- 支付、套餐、自动续费和计费系统。
- 脚本多人协作编辑、跨账号共享/市场、审批流水线、定时触发和通用工作流编排。
- 邮件发送服务尚未配置时的邮箱验证注册和密码找回；首版注册不要求验证邮箱。

验收重点是：普通用户登录只看到个人工作区，不能读取或改变其他用户资源；用户能创建个人任务、编辑草稿并刷新/重新登录后恢复，发布不可变版本、查看差异并回切；随后选择自己在线设备执行已发布脚本、查看实时状态与历史并停止任务。管理员仍可进入全局管理工作区。手机竖屏/横屏、平板和桌面浏览器中上述关键操作均可完成，无遮挡且保存/运行状态清晰。越权 API 请求均被拒绝并有授权测试；脚本只在获授权 Android 设备执行；无权设备无法下载或运行脚本；发布或哈希校验失败不破坏此前可用版本；草稿保存失败明确反馈且不丢内容。

## 9. 主要风险与前置验证

1. **Python Android 兼容性：**Chaquopy 支持的 Python 版本、ABI、依赖包和原生扩展需逐项验证。MVP 固定 Python 版本、ABI 和依赖白名单，不承诺所有 PyPI 包均可运行。
2. **无障碍与屏幕捕获：**能力设计必须遵循 Android 系统授权，不能承诺绕过系统限制。
3. **任务可靠性：**Android 电量优化、进程回收和设备厂商差异会影响长任务。首版以已登录设备发起的短时、可见前台任务为准；不能保证离线设备收到请求或系统限制下自动启动。需要 Android 系统授权的远程任务仍须用户完成系统授权。

建议先做 Android 技术验证原型：选定目标 Android 版本和一个自动化场景，验证 Chaquopy 调用 Kotlin 桥接、权限授权、任务中止及目标渠道政策，再投入完整后台开发。
