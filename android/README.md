# FlowPilot Android 客户端

原生 Kotlin/Jetpack Compose 客户端支持普通用户邮箱注册和登录、绑定设备、同步任务版本、校验脚本 SHA-256，并显示当前运行状态、本地日志及最近 10 条服务端运行历史。控制端与受控端的历史记录卡片均可点击查看任务、状态、版本、设备、起止时间、结果和运行标识详情；已结束运行从历史中查看，不另设“最近一次运行”卡片。当前执行中的任务仍显示必要状态、日志和停止操作。设备用户可从“任务”页直接启动脚本；控制端远程派发的授权任务由受控端自动启动。Python 3.12 由 Chaquopy 在 App 进程内运行。演示后端仍只负责账号、授权、脚本分发和运行记录，不会执行 Python。

## 后续客户端需求

客户端支持普通用户自助注册及常用账号体验：姓名/邮箱/密码注册（首版不强制邮箱验证）、登录/退出、加密保持登录、令牌自动续期及会话失效后自动返回登录页、个人资料查看/修改和登录后修改密码。邮箱修改须验证当前密码；修改密码会注销其他会话，当前设备保持登录。管理员不可通过公开注册创建。服务端已提供邮件验证码重置 API；Web 和两个 Android 客户端仅在 API 报告 SMTP 已配置时显示找回入口，投递服务应先完成运维验收。

## Android 客户端账号页面规范

控制端和受控端的“我的”页面保持一致：个人资料头像与姓名/邮箱头部、个人资料与账号安全分组、帮助与关于入口、主色“退出登录”按钮；资料和密码分别进入独立编辑页，支持页面内返回及系统返回。个人资料页允许修改姓名和邮箱，仅修改邮箱时需要当前密码；账号安全页要求输入当前密码及至少 6 位新密码。页面文案、布局或交互调整只在此处维护规范，并同步修改两个客户端。

产品需求现明确控制端和受控端是两个分开的 Android 应用：控制端 App 负责查看本人有权操作的设备、下发/跟踪/停止任务，不包含脚本执行运行时；受控端 App 绑定设备并接收/执行任务，不提供控制其他设备的派发界面。它们与 Web 控制台共用账号、服务端 API 和设备授权规则，可复用非 UI 代码，但必须独立安装和发布。当前 `:controller` 是控制端 MVP，支持普通用户注册/登录、在线设备优先列表、多选设备和脚本后批量派发、对同一设备持久排队、取消等待中的请求、请求停止运行中的远程任务并跟踪状态；`:app`（包名 `com.flowpilot.android`）是受控端。远程停止请求会由受控端轮询，并在脚本下一个停止检查点响应；它不会强制终止任意阻塞代码。本 README 后续的首次使用说明记录的是受控端能力。
客户端按服务地址、账号、设备和任务隔离保存最近两个成功校验的脚本版本；执行时使用指定的发布版本，缓存未命中则从服务端下载并校验，下载或校验失败时不会改为运行其他版本。用户可解绑本机设备；任务执行期间禁止解绑。缓存不是沙箱或安全保证，运行仍需服务端授权和 Android 系统权限。
两个 Android 应用均提供“帮助与关于”入口，显示对应应用版本、操作指引，以及系统授权和协作式停止行为的限制。

客户端使用与 Web demo 一致的浅灰底色、FlowPilot 绿色强调色、渐变欢迎横幅和白色圆角卡片；底部导航使用白色圆角浮层和浅色选中提示。控制端信息卡片、设备选择卡片和任务选择卡片均统一使用与受控端一致的 18 dp 圆角、1 dp 描边和 2 dp 阴影，选中状态仍以主题色底和描边突出。
设备在线、运行成功、执行中、离线和结束状态使用与 demo 对应的语义状态徽标，便于快速区分当前状态。
任务卡突出任务图标与发布版本；远程待命和无障碍授权状态也会以徽标显示。
任务所有者或已获任务访问权限的用户，其设备会自动同步当前发布版本；无需逐台发布脚本、设备确认接收或额外设备版本授权。受控端校验 SHA-256 后缓存脚本。用户只能从 Web 或控制端向自己名下的设备派发运行；管理员可以管理任务访问权限和查看运行记录，但不能直接启动其他用户设备上的任务。同设备的批量请求由服务端按顺序持久排队，一次仅向受控端提供队首，前一项结束后再提供下一项。控制端派发的远程运行请求在服务端校验通过后由设备自动启动，不需要逐次任务确认；请求卡显示脚本版本、来源、发起人、有效期和声明能力。屏幕捕获、无障碍等 Android 系统权限仍须用户按系统提示授予。Python 脚本执行环境提供标准 `__name__ == "__main__"` 入口；执行失败的详细原因会保留在设备本地运行日志中。服务端仍校验账号、设备归属、任务访问权限和请求有效期。

## 构建

- Android Studio（Android Gradle Plugin 8.7.3）
- JDK 17 或更新版本
- Android SDK Platform 35 和 Build Tools 35

Debug 构建为了可信局域网内的演示服务显式允许 HTTP；Release 构建默认禁止明文流量，应配置 HTTPS API 地址。不要把 Debug APK 用于正式分发或连接不可信网络。

在 Android Studio 中打开 `android/`，或执行：

```bash
cd android
./gradlew :app:assembleDebug
./gradlew :app:testDebugUnitTest
./gradlew :controller:assembleDebug
./gradlew :controller:testDebugUnitTest
```

APK 位于 `android/app/build/outputs/apk/debug/app-debug.apk`。当前配置为私有 APK，支持 `arm64-v8a` 真机和 `x86_64` 模拟器。
独立控制端 APK 位于 `android/controller/build/outputs/apk/debug/controller-debug.apk`，包名为 `com.flowpilot.controller`。控制端详细范围和已知限制见 [`controller/README.md`](controller/README.md)。
连接已启用 USB 或无线调试的设备后，可运行 `./gradlew :app:connectedDebugAndroidTest` 验证 Python 桥接及设备端 OCR；OCR 使用本地生成的测试图，不需要开启无障碍或屏幕捕获权限。
GitHub Actions 会运行两个模块的 JVM 单元测试及 Debug 构建；需要连接真机/模拟器的 instrumentation tests 不在无设备的 CI job 中执行。

### 私有 APK 发布

官网/私有服务器分发不经过 Google Play 审核，但 Android 要求每个 APK 都经过签名；用户还须允许其下载来源安装未知应用（参见 [Android 替代分发指南](https://developer.android.com/distribute/marketing-tools/alternative-distribution)）。构建 Release APK 前，使用离线安全保存的发布密钥配置以下环境变量，不要将密钥、密码或签名 APK 提交到仓库：

```bash
export FLOWPILOT_RELEASE_STORE_FILE=/secure/path/flowpilot-release.jks
export FLOWPILOT_RELEASE_STORE_PASSWORD='从密钥管理器读取'
export FLOWPILOT_RELEASE_KEY_ALIAS=flowpilot
export FLOWPILOT_RELEASE_KEY_PASSWORD='从密钥管理器读取'
cd android
./gradlew :app:assembleRelease
```

Release APK 输出到 `android/app/build/outputs/apk/release/app-release.apk`。所有后续版本必须继续使用同一发布密钥，并递增 `versionCode`，否则 Android 不会将其视为可覆盖升级。发布密钥应离线备份并限制访问；密钥丢失后，已有安装无法通过同一包名正常升级。Debug APK 仅用于开发/测试。

该渠道要求用户主动安装 APK，不会绕过未知来源安装确认。Android [动态代码加载安全指南](https://developer.android.com/privacy-and-security/risks/dynamic-code-loading)将远程加载可执行代码视为高风险；当前产品从服务端获取并在 App 进程中解释 Python 脚本，必须仅使用自有可信服务、TLS、服务端授权和客户端哈希校验，且不能将哈希或用户确认描述为安全沙箱。APK 签名与升级要求见 [Android 应用签名指南](https://developer.android.com/studio/publish/app-signing)。若未来改为 Google Play 分发，需重新评估其针对动态代码加载的上架政策。

## 首次使用

1. 启动仓库的演示服务：`make dev`。模拟器 API 地址为 `http://10.0.2.2:8001`；真机请使用启动器输出的 LAN API 地址，并在登录页确认/修改服务地址（客户端保存的地址可能是上次测试地址）。例如，2026-10-14 本地开发机地址为 `http://192.168.0.105:8001`，这是动态局域网地址，不是固定默认值。手机与开发机需连接同一可信任局域网；该服务无 TLS，不要暴露到公网。
2. 新用户可在登录页点“没有账号？注册”，填写姓名、邮箱和至少 6 位密码。首版不要求邮箱验证，邮箱须唯一；注册仅创建普通用户，管理员账号仍由后台管理员初始化/创建。注册成功后使用该账号登录并绑定设备。管理员账号只能用于 Web 管理后台。设备绑定时记录设备型号和当前 App 版本；App 每次发送心跳时会同步更新版本，便于管理员识别已升级设备。
   登录页默认勾选“记住登录信息”，API 地址、邮箱和密码会保存在 Android 加密偏好设置中，方便下次测试；取消勾选会清除已保存的登录信息。登录令牌仍单独加密保存；退出登录会清除本机令牌并请求服务端撤销当前会话，账号信息保留以便再次登录。
3. 登录并绑定设备后，App 默认开启远程运行待命，并按 Android 系统流程请求通知、电池优化和持续屏幕捕获授权。设备页将设备信息和三项状态收在简洁卡片中：无障碍操作、远程运行待命、屏幕捕获；型号与设备名称相同时只显示一次。每项均以按钮显示；未开启时按钮为“开启”，已开启时显示灰色“已开启”按钮。返回 App 时会更新系统权限和待命状态，前台运行期间远程请求自动刷新。通知权限被拒绝时无法开启可见的远程待命服务；无障碍和屏幕捕获仍由用户按系统流程授权。若 Android 结束进程或撤销屏幕共享，持续 OCR 会话无法静默恢复，需重新授予屏幕捕获权限。
4. 演示账号默认分配了“抖音订单状态 OCR 演示”任务 `v1.7.0`。任务卡片显示发布来源、版本和能力说明；点击“启动”后，App 下载并校验脚本，再按 Android 系统流程请求需要的屏幕捕获或无障碍权限。识别到的状态只显示在设备本地，不点击、不上传 OCR 内容。
5. 在控制端选择在线设备和脚本并派发，受控端无需确认接收或逐次确认任务。首次使用时按系统提示授予任务所需的屏幕捕获、通知或 **FlowPilot 自动化操作** 无障碍权限。受控端任务页也可直接启动已发布任务。抖音自动化仅允许访问抖音 `com.ss.android.ugc.aweme` 或抖音极速版 `com.ss.android.ugc.aweme.lite`，且最多点击每次运行指定的一处可点击文字。若两者都安装，优先打开抖音主版。
6. 登录并绑定设备后 App 会自动请求开启“持续 OCR 待命”，Android 显示屏幕捕获系统授权；同意后 FlowPilot 以独立前台服务维持该捕获会话，并显示持续通知及停止按钮。若首次拒绝，可在设备页“屏幕捕获”行点击“开启”重新授权。待命期间，所有远程 OCR 任务可复用当前会话，不必每个任务都再次弹系统授权。退出待命、系统回收进程/投屏、重启设备或 Android 撤销共享后，会话结束，下次 OCR 需重新授权。此授权不能登录时预先授予、跨会话保存或永久保活。没有开启持续待命时，单次 OCR 仍在任务开始时由 Android 系统弹出授权。任务运行期间 OCR 文本保留在设备本地；上报到演示 API 的运行摘要仅包含通用状态。
7. App 前台每 15 秒发送一次设备心跳并刷新远程请求；进入后台后停止前台轮询。远程待命服务每 15 秒发送设备心跳并轮询一次，运行时显示持续通知；设备超过 2 分钟没有心跳会显示为离线，离线设备不会接受新的远程运行请求。控制端设备页每 5 秒刷新服务端设备状态；状态由心跳更新，离线判定仍使用 2 分钟心跳超时。登录、返回 App 前台或手动点击“同步”时会同步已授权任务。所有远程请求在服务端鉴权和设备空闲检查通过后由客户端自动批准并启动，无需逐任务审阅、确认或配置预授权；任务仍可在设备上停止。请求所需的无障碍能力必须已在 Android 设置中启用；屏幕捕获能力仍须由 Android 系统授权。App 前台收到 OCR 请求时会弹出 Android 屏幕捕获授权（若尚无有效持续 OCR 会话）；后台收到时会通知用户打开 App 完成系统授权。持续 OCR 会话结束或被系统回收后需要重新授权。

## Python 桥接接口

脚本在全局变量 `bridge` 上可用以下方法：

- `bridge.open_douyin()`：打开已安装的抖音；若已在抖音前台则不重复启动。
- `bridge.wait_for_douyin(timeout_seconds=15)`：等待抖音主版/极速版进入前台，超时范围为 1–30 秒；用于避免启动动画或系统切换期间过早截图，用户停止任务时会尽快结束等待。
- `bridge.ocr()`：OCR 当前屏幕并返回识别文本；仅在抖音处于前台时允许。
- `bridge.click_text(text)`：按无障碍节点文字执行一次点击；每次任务最多一次，且只能作用于抖音主版或极速版。
- `bridge.log(message)`：将最多 4 KB 的当前运行日志保留在本机；开始新运行时清空上一运行的日志。
- `bridge.is_stopped()`：查询用户是否已请求停止。脚本应在循环中检查该值，并及时退出。

最小脚本示例见 [`examples/open_douyin.py`](examples/open_douyin.py)。若任务名称包含“抖音”，客户端会在执行前启动抖音；脚本仍应调用 `bridge.open_douyin()`，以便在远程恢复或 App 切换场景下确保目标应用已打开。

## 权限和安全边界

- Android 不允许 App 静默授予 MediaProjection 屏幕捕获权限，也不允许 App 代替用户启用无障碍服务；本客户端不会绕过这些系统限制。远程任务在服务端校验后自动运行，不需要逐任务审阅或确认；但 OCR/屏幕捕获仍须通过 Android 系统授权，未启用的无障碍能力仍须由用户在系统设置中启用。系统拒绝授权则不执行。本地运行同样遵循正常系统授权流程。持续 OCR 是用户主动开启的单次可见会话，不是永久权限或后台静默保活。
- 通知权限、忽略电池优化和屏幕捕获授权均由 Android 系统弹窗/设置页授予，App 无法静默开启；无障碍服务也必须由用户手动启用。系统电池豁免有助于后台待命，但不能绕过厂商自启动/后台限制或保证永久保活。远程待命运行期间必须保留用户可见的前台服务通知。
- Python 脚本在 App 进程内运行，**不是安全沙箱**。点击启动会直接执行任务，不提供逐次脚本审阅确认；SHA-256 只检测下载内容变化，不隔离恶意脚本。只运行来自可信发布者且经管理员审查授权的代码。
- 当前 OCR 使用设备端 ML Kit；截图和 OCR 文本不上传。用户脚本本身具有 App 进程权限，可能访问 App 可访问的数据或网络。
- 演示 API 默认使用无 TLS HTTP 和演示账号。不要在不可信网络、生产账号或公网部署中使用。
- 目前只面向中国版抖音和抖音极速版，不包含无障碍手势、多次点击或其他应用自动化。
